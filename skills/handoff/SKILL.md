# handoff · 会话换人

**换人 = 旧会话收口 + 继任者启动。** 继任者怎么起来，先看应用给了哪个工具，再看这一轮是谁开的：

| 路径 | 条件 | 用户要做什么 |
|---|---|---|
| **A 直接启动** | 有 `mcp__ccd_session__start_session`，且本轮里有用户本人在这个窗口说的话 | 无 |
| **B 提议卡片** | 有 `start_session`，但本轮由别的会话的消息、定时任务或后台通知开启 | 点卡片，或回这个窗口说一句「启动」 |
| **C 芯片** | 只有 `mcp__ccd_session__spawn_task`（两个工具互斥，清单里有哪个走哪个） | 点芯片 |

**想零点击，就请用户在桌面端、到要换人的那个窗口说一句「换人」。** 手机经远程控制发来的话不算本人输入，卡片和芯片在手机上也看不到（均为 2026-10-14 实测）。人在手机上时，唯一的路是新建会话粘贴交接文档里的继任 prompt。 B 是应用有意设的闸：不重试、不托别的会话代启动、不换别的工具绕过去。

与 `ctx-watch` 相互独立：那边只管报水位，这里只管执行换人。任何水位都可以跑；演练标记 `[test]` 的位置见第 5 步，永远不进 `title`。

## 三方分工

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| **旧会话** | 现跑事实 → 释放绑定 → 写交接文档 → 改名下班 → 启动继任者 → 待命 | 不归档自己；不通知协作方；不接新任务 |
| **继任者** | 脱离前任 → 确认标题 → 读交接文档 → 定位自己并核对 git → 通知协作方 → 续跑 | 不重新推导旧会话已定的结论 |
| **用户** | 在桌面端要换人的窗口说一句「换人」；没直接起来时点一下卡片或芯片 | 其余全不用管 |

**为什么由继任者通知协作方**：继任者的会话 id 只在它启动后才存在，而且同名会话常有好几条。继任者用自己的 id 自报家门，不会认错人。

## 旧会话：六步

1. **现跑事实，不引用记忆。** 水位（装了 [ctx-watch](https://github.com/juew/ctx-watch) 时）`node <ctx-watch>/scripts/ctx-audit.mjs`，真实窗口是 1M 而机器上没有会话接近过它时加 `CTX_WINDOW=1000000`；`git status --short | head`、`git log --oneline -5`、`git worktree list`；报告里任何计数都要有产生它的命令。
2. **释放会话级绑定并留证。** Artifact watch（`status` → `unwatch`）、后台任务、Monitor、锁、看板订阅——逐项实测释放，把命令与结果写进交接文档。拿不到证据的写「未确认」，不写「已释放」。
3. **写或更新交接文档。** 位置按项目或全局 `CLAUDE.md` 里既定的交接文档约定，没有约定时放 `<项目根>/docs/handoff-<项目名>.md`；该会话已在维护的文档直接更新，同一项目多角色并行时按角色分文件 `交接-<项目名>-<角色>.md`，各角色文件相互独立。必含四项（已改文件/函数、剩余任务、验证证据含 EXIT 码、踩坑清单）之外，本 skill 再加三节：
   - **对接名单**：现跑 `mcp__ccd_session_mgmt__list_sessions`，列出协作会话的标题 + `local_…` 会话 id + 各自正在等你什么。id 不会变，显示名会重
   - **继任者启动清单**：继任者要做的事，按顺序，可勾选
   - **继任者启动 prompt**：第 5 步 `prompt` 的完整原文（模板每个 `<…>` 已填成具体值）。这是兜底：继任者没能直接起来、用户又点不到卡片时，开一个新会话把这段贴进去即可
   密钥、Token、连接串只写变量名与获取途径。
4. **改名下班。** `get_session("self")` 取原名，再 `set_session_title("self", "<原名>(<时间戳>下班)")`，时间戳用 `date '+%Y年%m月%d日%H:%M:%S'`，例：`M·AI小程序PM(2026年09月02日09:51:09下班)`。这个改名只写桌面端本地存储，手机/远程端列表看不到，那里新旧两个会话会同名——所以第 6 步回复正文必须以「本会话已下班」开头，远程用户靠正文分辨。
5. **启动继任者。** 按下一节选 A / B / C。文档没落盘不许走到这一步。
6. **告诉用户并待命。** 一句话，以「本会话已下班」开头，加交接文档路径，再按路径说清用户要不要动手：
   - A：「继任者已直接启动（`local_…`），不用点任何东西」
   - B：「应用没让我直接启动（<原因>）。已出提议卡片：在桌面端点它（要落在主 checkout 请下拉选 `Start locally`），或回这个窗口说一句『启动』」。原因如实写：本轮由别的会话或自动事件开启；用户明明说了换人仍被拒，多半因为他在手机上，远程发来的话不算本人输入。照抄应用的拒绝原话，不替它另编理由
   - C：「芯片已出，点它；要落在主 checkout 请下拉选 `Start locally`」
   - B、C 再加一句：「卡片/芯片在手机上看不到。你在手机上时，新建会话粘贴交接文档里的继任 prompt，期间我继续待命」
   之后不再接新任务，不循环等待，不 `archive_session("self")`——归档由用户在继任者确认接手后决定。唯一例外：B 之后用户回来说「启动」，带 `proposal_id` 调一次 `start_session`。

## 第 5 步：启动继任者

### A 直接启动

本轮里有用户本人在这个窗口说的话（由它开启，或中途插进来，都算）：

```json
{"initiation": "user_asked", "context": "fresh", "use_worktree": false,
 "title": "<原名>", "name": "<短名，[a-z0-9-]，不超过 24 字符>",
 "background": "<不少于 80 字：项目、这条线的角色、为什么换人、交接文档路径>",
 "prompt": "<下面模板填满后的全文>"}
```

返回 `Started session "<原名>" (session_id: local_…)` 才算启动，把这个 id 写进交接文档。

- **`title` 一字不差写原名**，不写「接手 <原名>」：手机/远程端的会话列表只认创建时的标题。
- **`context` 只用 `"fresh"`**，`background` 与 `prompt` 两个都必填。`"fork"` 和 `hand_off_to_session` 会把整段对话抄给继任者，换人要甩掉的正是它。
- **`use_worktree` 看自己在哪。** 在主 checkout（`git worktree list` 第一行是自己）传 `false`，继任者落在同一处。自己在 worktree 里传 `true`：传 `false` 继任者只是寄居在这个 worktree，脱离不了前任，前任一归档它就被封编辑。`true` 从本分支尖端切新 worktree，**未提交的改动带不过去**——改名之前先把未提交清单报给用户，由用户决定是否提交，再启动。用户选不提交时，把这些文件的绝对路径写进交接文档，继任者按路径去旧 worktree 读。
- **演练**：`background` 第一行写 `[test]`。
- **这一步必须落在用户那句话所在的这一轮。** 前四步不用后台任务、后台子 agent：等它们回来已是「通知开启的一轮」，会被拒。前台子 agent 在本轮内返回，可以用。需要问用户就直接问，用户的回答会开启新的一轮，照样算数。
- **用户在手机上经远程控制说的「换人」不算数**（2026-10-14 实测被拒，原话与 B 节相同）。照常先试 A，被拒走 B，第 6 步给出手机兜底。

### B 提议卡片

本轮没有用户在这里说的话，或者 A 被拒（原话以 `Start sessions only on the user's own words to you here` 开头）：参数同 A，`initiation` 改 `"own_initiative"`，不带 `cwd`、`host`、`environment`、`preset`（卡片不收落点参数）。返回 `Proposed "<原名>" (task_id: task_…)`，把 task_id 写进交接文档。

用户点卡片即启动。卡片与旧芯片是同一个组件，主按钮同样是 `Start with worktree`，而且手机端不显示（均为 2026-10-14 实测）；传了 `use_worktree:false` 后点主按钮落在哪未实测，所以照样提醒用户下拉选 `Start locally`。用户回这个窗口说「启动」时，调 `start_session` 只带 `proposal_id`（值就是那个 `task_…`），别的参数都不传。这一步过的是同一道闸：从手机回的「启动」按会被拒对待（未单独实测）。

### C 芯片

工具清单里没有 `start_session`、只有 `spawn_task`：`title` = `<原名>`，`cwd` = 项目根目录，`prompt` = 模板全文，`tldr` 一句话，演练标记 `[test]` 放 `tldr`。主按钮 `Start with worktree` 会在**新 worktree** 里启动继任者；`Start locally` 才落在主 checkout；`Fix in this session` 会把 prompt 灌回本会话，不可选。

## 继任 prompt 模板

```
你是「<原名>」的继任者，原会话已改名为「<原名>(<时间戳>下班)」并停止接活。
1. 先脱离前任：ToolSearch 取 mcp__ccd_session_mgmt__detach_session，session_id 传 "self"。不脱离的话你每一轮结束都会叫醒已下班的前任。被拒（你是用户点卡片/芯片启动的，或你与前任共用 worktree）就跳过，把拒绝原话写进交接文档
2. get_session("self") 确认标题已是「<原名>」；不是才 set_session_title("self", "<原名>")
3. 读交接文档：<绝对路径>。以它为准，不重新推导已定结论
4. 先 git worktree list 确认自己启动在主 checkout 还是新 worktree。再核对：git -C <主 checkout 绝对路径> status --short；git -C <主 checkout 绝对路径> log --oneline -3；主 checkout 分支应为 <branch>，自己所在 worktree 的分支不同不算异常。把所在位置写回交接文档
5. 按文档「对接名单」逐个通知：SendMessage，to 填名单里的 local_… 会话 id（没有 SendMessage 时用 mcp__ccd_session_mgmt__send_message）。内容：「我是 <原名> 的继任者，会话 id <get_session 返回的 sessionId>，原会话已下班；你手上等我的 <事项> 由我接」（每条 ≤400 字，summary 必填）
6. 直接向用户报一句「接手完成」，附脱离结果与对接名单通知结果。不经前任转述
7. 从「剩余任务」第一项续跑
```

模板里每个 `<…>` 都必须由旧会话填成具体值，不留占位符（第 5 项的会话 id 由继任者自己取，照抄这句说明即可）。

## 常见错误

| 错误 | 纠正 |
|---|---|
| 有 `start_session`、用户也在本窗口说了换人，仍出卡片或芯片等用户点 | 这种情况走 A，零点击。卡片只在 B 出现 |
| 本轮是别的会话（如 PM）发消息开启的，却指望直接启动 | 那一轮里没有用户本人的话，应用必拒，只能 B。想零点击，请用户去那条线的窗口说一句 |
| 用户人在手机上，以为说一句「换人」就能零点击 | 远程发来的话不算本人输入，A 必拒；改出的卡片手机上也看不到（均实测）。零点击只能在桌面端说；人在外面时，交接文档里的继任 prompt 是唯一兜底 |
| A 被拒后反复重试、改用 `offer`、或托别的会话代为启动 | 都是绕闸。直接走 B，并把原因告诉用户 |
| 用 `hand_off_to_session` 或 `context:"fork"` 换人 | 整段对话会被抄给继任者。只用 `"fresh"` |
| `"fresh"` 没写 `background`，或少于 80 字 | 调用被拒。`background` 不能代替 `prompt`，两个都要 |
| 先起后台任务，等通知回来再启动继任者 | 通知开启的一轮没有用户输入，A 被拒。启动必须落在用户说换人的那一轮 |
| 旧会话在 worktree 里仍传 `use_worktree:false` | 继任者寄居前任的 worktree，脱离不了、前任归档后被封编辑。传 `true`，先处理未提交改动 |
| 继任者没有脱离前任 | 每轮结束都叫醒已下班的前任，而它的上下文通常最大。模板第 1 项 |
| 给提议卡片带 `cwd`/`host`/`preset` | 卡片不收落点参数，调用报错。去掉 |
| 先启动继任者、事后再补交接文档 | 文档没落盘，继任者拿到的就是空壳。第 3 步在第 5 步之前 |
| 「用户没说通知谁，所以不通知」 | 通知是接手的一部分，由继任者按「对接名单」做 |
| 改名成自创标记（如「【已收口】」） | 固定格式 `(<时间戳>下班)`，侧边栏靠它按时间排 |
| 启动完继任者就 `archive_session("self")` | 归档由用户在继任者确认接手后决定；卡片或芯片没被点前归档，交接文档之外的一切随之消失 |
| 「看板订阅应该已经释放了」 | 没有命令与结果就写「未确认」 |
| 继任 prompt 只写「读交接文档继续」 | 七项清单缺一不可，尤其脱离、确认标题与通知 |
| `title` 写「接手 <原名>」，指望继任者改回 | 手机/远程端列表只认创建时的标题，改名它看不到。名字一次写对 |
| 以为改名「(…下班)」后手机端也能分清新旧会话 | 改名远程端不可见，远程列表新旧同名。下班声明写进第 6 步回复正文 |
| 用户在手机上，旧会话出完卡片或芯片就以为换人完成 | 卡片与芯片都只在桌面端显示（芯片 2026-09-02、卡片 2026-10-14 实测）。交接文档必须带「继任者启动 prompt」一节供粘贴；旧会话继续待命 |
| 继任者把「分支应为 X」套在自己所在的 worktree 上 | 继任者可能启动在新 worktree。git 核对一律带 `-C <主 checkout>`，先 `git worktree list` 定位自己 |
